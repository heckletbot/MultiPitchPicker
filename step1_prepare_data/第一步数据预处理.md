# 第一步：数据预处理

本步把已经采集好的半音阶录音，整理成训练脚本 `train.py` 所要求的输入。

采集要求见 `[音频采集指南.md](音频采集指南.md)`。原始音频本仓库不附带。马林巴可从 [Iowa MIS](https://theremin.music.uiowa.edu/MIS.html) 下载；其它乐器按同一规范自行采集。

预处理结束后应得到两套数据：

1. **单音库**：每个文件对应一个音高、一次击奏；并有一份索引，写明路径、音高、力度、音色。
2. **合成训练集**：用单音按和弦模板叠成 8 秒片段，每条片段带精确的音符标签，并预先算好 CQT 特征。

本目录 `[config.py](config.py)` 的 `MIDI_LO` / `MIDI_HI` 必须与采集音域、同目录 `[config_prep.json](config_prep.json)` 一致。改音域后须重跑本步。

依赖（在仓库根目录 `MultiPitchPicker/` 下执行）：

```bash
pip install -r step1_prepare_data/requirements.txt
```

## 原始半音阶从哪里来

Iowa 马林巴一条常用原始文件是「一种槌、一档力度、一个八度」：`Marimba.yarn.pp.C2B2.aif` 表示纱槌、弱奏、C2 到 B2 共 12 个音，每个音敲一下。滚奏（roll）、闷音（deadstroke）默认不使用。

```bash
python step1_prepare_data/scripts/01_download_iowa_marimba.py
python step1_prepare_data/scripts/run_pipeline.py
```

对于新乐器模型训练，自行采集的音频先按文件名规范放进目录，或用 CSV（`path,midi,dynamic,timbre`）登记逐条单音：

```bash
python step1_prepare_data/scripts/02_ingest_raw.py --src <半音阶或单音目录>
python step1_prepare_data/scripts/run_pipeline.py --raw step1_prepare_data/work/raw/inbox
```

`--smoke` 只合成几十条 8 秒片段，用来检查切分是否正确，再跑全量。参数见 `config_prep.json`。

## 预处理流水线

正式流水线是 **03–09**，由 `scripts/run_pipeline.py` 按序调用。**01、02 是辅助脚本，不是必须步骤**：半音阶已经在本地时跳过 01；文件已在 `work/raw/` 且文件名符合规范时跳过 02。路径均相对 `step1_prepare_data/`，`09` 的 `data/` 在仓库根目录。

| 步骤 | 类型 | 对应文件 | 作用 | 输入 → 输出 |
| --- | --- | --- | --- | --- |
| 01 | 辅助（可选） | `scripts/01_download_iowa_marimba.py` | 下载 Iowa 马林巴半音阶音频 | 网页链接（`config_prep.json` 的 `iowa_page`）→ `work/raw/iowa_marimba/Marimba.yarn.pp.C2B2.aif` 等半音阶文件 |
| 02 | 辅助（可选） | `scripts/02_ingest_raw.py` | 把自采音频或 zip 收进统一目录 | `--src` 文件夹 / zip，或 `--sheet` CSV → `work/raw/inbox/` 下的音频（CSV 时会按表改名） |
| 03 | 正式 | `scripts/03_split_chromatic.py` | 半音阶长文件切成单音 | `work/raw/iowa_marimba/*.aif`（或 inbox）→ `work/split/C2.yarn.pp.wav` 等 + `work/split/split_manifest.jsonl` |
| 04 | 正式 | `scripts/04_resample_16k.py` | 转为 16 kHz 单声道 16-bit PCM | `work/split/*.wav` + `split_manifest.jsonl` → `work/singles/C2.yarn.pp.wav` + `work/singles/resample_manifest.jsonl` |
| 05 | 正式 | `scripts/05_build_index.py` | 生成单音索引 | `work/singles/resample_manifest.jsonl` → `work/singles/index.raw.jsonl` |
| 06 | 正式 | `scripts/06_qc_pitch.py` | 估计基频，填写 `winner_midi` | `work/singles/index.raw.jsonl` + 对应 wav → `work/singles/index.qc.jsonl`、`work/reports/pitch_qc.json` |
| 07 | 正式 | `scripts/07_filter_clarity.py` | 丢掉音级不符的行，每音高留最清晰的 K 条 | `work/singles/index.qc.jsonl` + wav → `work/singles/index.jsonl`、`work/reports/clarity.json` |
| 08 | 正式 | `scripts/08_report_coverage.py` | 检查音域覆盖 | `work/singles/index.jsonl` → `work/reports/coverage.json` |
| 09 | 正式 | `scripts/09_make_synth_and_cqt.py`（调用本目录 `scripts/synth_clips.py`、`scripts/precompute.py`） | 安装单音库、合成 8 秒片段、预计算 CQT | `work/singles/index.jsonl` + wav → `data/singles/index.jsonl` 与 wav；`data/synth/{train,validation,test}.jsonl`、`wav/` 下 8 秒片段、`*.wav.cqt285.npy` |

在仓库根目录 `MultiPitchPicker/` 下执行。03–09 也可一次跑完：

```bash
python step1_prepare_data/scripts/run_pipeline.py
```

自采音频已收进 inbox 时：`python step1_prepare_data/scripts/run_pipeline.py --raw step1_prepare_data/work/raw/inbox`。先小规模试跑加 `--smoke`。

分步命令：

```bash

# 04–08 正式
python step1_prepare_data/scripts/04_resample_16k.py
python step1_prepare_data/scripts/05_build_index.py
python step1_prepare_data/scripts/06_qc_pitch.py
python step1_prepare_data/scripts/07_filter_clarity.py

# 09 正式；--smoke 只合成 32/8/8 条
python step1_prepare_data/scripts/09_make_synth_and_cqt.py --smoke

```

## 预处理完成后的数据格式

处理好后放入训练真正读取的 `data/ 下`。

```
MultiPitchPicker/data/
├── singles/                          # 合格单音库
│   ├── index.jsonl                   # 一行一个单音
│   ├── C4.yarn.mf.wav
│   ├── C4.cord.ff.wav
│   └── …
└── synth/                            # 合成多音片段（train.py 的 --data）
    ├── train.jsonl                   # 训练集清单
    ├── validation.jsonl              # 验证集（默认留出音色）
    ├── test.jsonl                    # 测试集（默认留出音色）
    ├── manifest.json                 # 合成时的采样率、和弦模板、音色划分等
    └── wav/
        ├── train/
        │   ├── clip_train_000000.wav
        │   ├── clip_train_000000.wav.cqt285.npy
        │   └── …
        ├── validation/
        └── test/
```

### `data/singles/index.jsonl`

每行一条 JSON。`wav` 相对仓库根目录。`dynamic` 只能是 `pp` / `mf` / `ff`。`winner_midi` 与 `midi` 不同则该行不参与合成。

```json
{"wav": "data/singles/C4.yarn.mf.wav", "midi": 60, "dynamic": "mf", "timbre": "yarn", "winner_midi": 60}
```


| 字段            | 含义                            |
| ------------- | ----------------------------- |
| `wav`         | 16 kHz 单声道 16-bit PCM，一次击奏加余振 |
| `midi`        | 标称音高编号                        |
| `dynamic`     | 采集时的力度档                       |
| `timbre`      | 音色变体（马林巴为槌名）                  |
| `winner_midi` | 质检得到的音高；可选                    |


### `data/synth/{train,validation,test}.jsonl`

每行一条 8 秒片段。`notes` 为该片段内全部音符，时间单位为秒，相对片段起点。

```json
{
  "id": "clip_train_000000",
  "audio": "data/synth/wav/train/clip_train_000000.wav",
  "timbre": "yarn",
  "duration_sec": 8.0,
  "notes": [
    {"midi": 60, "onset": 0.42, "offset": 1.80, "velocity": 96, "role": "melody"}
  ]
}
```


| 字段                         | 含义                          |
| -------------------------- | --------------------------- |
| `id`                       | 片段编号，与 wav 文件名对应            |
| `audio`                    | 8 秒、16 kHz、单声道 wav          |
| `timbre`                   | 本条合成所用音色；同条内各音共用            |
| `notes[].onset` / `offset` | 起止时间（秒）                     |
| `notes[].velocity`         | 1–127，合成时的响度与采样档            |
| `notes[].role`             | `melody` / `inner` / `bass` |


### `*.wav.cqt285.npy`

与对应 wav 同目录、文件名为 `<wav文件名>.cqt285.npy`。形状约为 `(285, 500)`（频率格 × 时间帧，8 秒、hop=256），float16，对数幅度并已按片段标准化。后续训练直接读该缓存；没有缓存时会现场计算并写入。

### `manifest.json`

记录本次合成的采样率、片段长度、和弦模板权重、力度区间、`train_timbres` / `heldout_timbres`、随机种子。供复查，训练不直接读它。

## Finish Check

- 抽听 `work/split/`：应是一次击奏、音高正确、余振完整，不要切进下一个音。
- `work/reports/pitch_qc.json` 中不一致条数应很少；大量八度错误检查是否切分音频错误。
- `work/reports/coverage.json`：音域中段不应有空洞。
- `data/synth/train.jsonl` 行数应接近设定的 `n_train`；打开一条 8 秒 wav，应能听到叠起来的旋律与和弦，而不是噪声或空轨。
