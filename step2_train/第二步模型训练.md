# 第二步：模型训练

本步输入是第一步的 `data/synth/`（8 秒片段 + CQT 缓存），说明见 `[../step1_prepare_data/第一步数据预处理.md](../step1_prepare_data/第一步数据预处理.md)`。  

本步输出：


| 产物         | 路径                                 |
| ---------- | ---------------------------------- |
| 基座         | `data/runs/base/best.pt`           |
| 最终模型（有真录时） | `data/runs/mix/best.pt`            |
| 推荐阈值 τ     | `step2_train/work/selected.json`   |
| 测试报告       | `data/runs/<run>/test_report.json` |


下一步才是导出 ONNX 给客户端。需要 CUDA GPU。Windows 可直接 `python`，不必 bash。

## 真录伪标（不是必须）

03 / 04 不是本步必跑项。没有 `data/real/` 整首独奏时：只训基座，再跑 05 扫阈值；导出用 `data/runs/base/best.pt`。一键命令加 `--skip-real`。

有干净独奏时才做这一块：

1. 把整首独奏放进 `data/real/`（采集方式见文末 [真录独奏采集](#真录独奏采集)）。
2. 基座训完后，`03_pseudo_label.py` 用基座在这些曲子上自动标音符，切成 8 秒片段，写出 `data/pseudo/train.jsonl`。
3. `04_merge_and_finetune.py` 把这些片段和一部分合成数据混在一起，微调出 `data/runs/mix/best.pt`。

真录音频是本步才提供的新数据；伪标清单是基座生成的，不是第一步预处理做出来的。没有真录就没有 mix，只用基座即可。

## 分步（对应原实验）

```
合成 train/val/test
  └─ 02 训基座 30ep，lr 3e-4          → data/runs/base/best.pt
        ├─ （无真录，默认）直接 05
        └─ （可选）03 基座 τ=0.3 给真录打伪标  → data/pseudo/train.jsonl
                 └─ 04 合成8000 + 伪标×2 混合，lr 1e-4 微调 8ep
                      → data/runs/mix/best.pt
                           └─ 05 合成 test 扫阈值，写出推荐 τ
```

```bash
python step2_train/scripts/02_train_base.py
python step2_train/scripts/03_pseudo_label.py          # 无真录跳过
python step2_train/scripts/04_merge_and_finetune.py    # 无真录跳过
python step2_train/scripts/05_eval_and_sweep.py
```

超参在 `[config_train.json](config_train.json)`。马林巴数字与原实验一致，换乐器主要改的是阈值（05 会重扫），不是先改 epoch。

低延迟变体：`02_train_base.py --lookahead`，且造数据时设过 `MP_CQT_GAMMA=2`。离线客户端不用开。

## 怎么看测试集指标

`05_eval_and_sweep.py` 在合成 **test** 上评测（默认是留出音色，训练时没见过），写出 `data/runs/<run>/test_report.json` 和 `step2_train/work/selected.json`。匹配规则：预测音与标注音 **音高相同**，起音时间差在 **±50 ms** 内算一对。

看这些字段：

| 字段 | 含义 |
|---|---|
| `n` | 测试片段条数 |
| `best_thresh`（τ） | 在 0.25–0.90 里扫一遍后，F1 最高的解码门槛。导出和客户端用这个，不要照抄马林巴的 0.8 |
| `precision`（P，精确率） | 报对的音 / 模型报出的全部音。低说明假音多（残响、泛音被当成新音） |
| `recall`（R，召回率） | 报对的音 / 标注里应有的音。低说明漏音多 |
| `f1` | P 和 R 的调和平均，综合好坏 |
| `velocity_mae` | 起音处力度误差（0–127 标度）。越小越好 |
| `sweep` | 每个 τ 对应的 P / R / F1，可看门槛高低如何换精确和召回 |
| `warn_f1_below_accept` | F1 低于 `config_train.json` 里的警戒线（默认 0.98）时为 true |

对照：马林巴 `bpm_mix` 在合成留出槌、τ=0.8 时约 P 99.5 / R 99.3 / F1 99.4，力度 MAE 约 7。打击键盘可把 F1 ≥ 0.98 当作 syntest 是否可用的参考；钢琴/吉他往往略低。数字明显差时先查单音库、切分和音域，不要急着导出。

训练过程中 `train.py` 每个 epoch 已在 **validation** 上扫 τ 并按 F1 存 `best.pt`。05 是在没参与存盘的 **test** 上再扫一次，给客户端用的 τ 以 05 为准。

## 真录独奏采集

本段只写微调用的**整首（整段）独奏**怎么准备。它和第一步的单音库不是同一种数据：

| | 第一步单音 | 这里的真录 |
|---|---|---|
| 内容 | 一个音敲一下 | 一首（或一段）连续演奏 |
| 用途 | 叠成 8 秒合成片段，训基座 | 基座在真录音上自动标音符，再微调 |
| 是否必须 | 必须 | **可选**。没有真录也能训，得到 `data/runs/base/best.pt`；有真录才会再训 `mix` |

没有真录时，模型在合成测试上可以很好，在真实录音上往往偏保守（听得见但少报音）。有干净独奏时，用基座以较低门槛在真录音上标出音符（伪标签：未经人工校对的自动标注），再和合成数据混在一起微调。

### 文件放哪里

```
MultiPitchPicker/data/real/
  曲子甲.wav
  曲子乙.mp3
  pool_filters.json    # 可选，用来切掉脏段落
```

格式：`wav` / `mp3` / `flac` / `m4a`。马林巴原实验大约 75 首，切成约 2170 条 8 秒片段。

### 录音要求

- 只有**正在训练的那一件乐器**。有人声、鼓、第二件乐器时，错误音高会被写进伪标签，比少录几首更差。
- 独奏、环境相对干净。手机录可以，不要用演出混音、伴奏带。
- 尽量覆盖这件乐器常见的音区、速度和力度。

### `pool_filters.json`（可选）

键是 `data/real/` 下的**文件名**，不是完整路径。用来丢掉或剪掉不能当独奏用的段落：

```json
{
  "talking_intro.mp3": {"exclude": true},
  "solo_then_band.mp3": {"keep_until_sec": 90},
  "applause_end.wav": {"trim_end_sec": 10}
}
```

| 字段 | 含义 |
|---|---|
| `exclude` | 整首不用 |
| `keep_until_sec` | 只保留开头 N 秒（例如后面乐队进来了） |
| `trim_end_sec` | 去掉末尾 N 秒（例如掌声） |

完整示例见 `[examples/pool_filters.example.json](examples/pool_filters.example.json)`。

有 `data/real/` 时，`03_pseudo_label.py` 用基座给这些曲子打标，默认门槛是 `config_train.json` 里的 `pseudo.thresh = 0.3`（低门槛，多标一些音）。这里不要改成 0.8；0.8 是合成测试上的解码门槛，不是伪标用的。
