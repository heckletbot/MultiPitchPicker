## 调用方法

### 命令行

```bash
python step4_api/scripts/transcribe_cli.py --audio song.wav --out notes.json
```

可选：`--thresh 0.8` 覆盖默认门槛；`--assets export` 指定模型目录（默认读 `[config_api.json](config_api.json)` 的 `assets`）。

不写 `--out` 时把同一份 JSON 打到标准输出。

等价底层入口：`python infer_onnx.py --audio song.wav --json notes.json`。

### Python

在仓库根目录：

```python
from infer_onnx import transcribe_file

result = transcribe_file("song.wav")
# result["notes"] → [{time, midi, note, velocity}, ...]
```

可选参数：`thresh`（float）、`assets`（ONNX 与 meta 所在目录）。

### 输入


| 项           | 规定                                                  |
| ----------- | --------------------------------------------------- |
| 音频          | 本地文件。`wav` / `mp3` / `flac` / `m4a` / `ogg` / `aif` |
| 模型          | `export/model.onnx` + `export/meta.json`            |
| `thresh`（τ） | 可选。onset 门槛；省略则用 selected / meta                    |


### 按帧接入（训练 8 秒，推理退化为 2 秒）

训练片段仍是 **8 秒**。命令行 / HTTP 的 `transcribe_file` 走整文件，内部仍按 8 秒时长输入与训练一致。

按帧实时接采集时，等不齐 8 秒也可以先推理：缓冲区凑满 **2 秒 = 32000 点** 再送进 ONNX。这是退化路径——CQT 仍按**当前这 2 秒**做标准化，和训练时的 8 秒统计量不一致，预测精度可能产生轻微劣化但是获得是更好的实时性。

- 采集帧（256 / 512 / 1024 点等）**不要**单独送进模型。
- hop = 256 点 ≈ 16 ms 是 CQT 时间格，不是一次调用的输入长度。
- PCM：单声道、`float32`、**16 kHz**；不是 16 kHz 先重采样再入缓冲。
- 手里只有这 2 秒 PCM 时，不要输入 `transcribe()` 或 `transcribe_file`（它们会补零到 8 秒）。用 `transcribe_chunk`：只把这 2 秒送进 ONNX，再解成 `notes`。

```python
import numpy as np
from infer_onnx import load_session, transcribe_chunk

sess, meta, _ = load_session("export")
buf = []
win_n = 2 * 16000   # 32000
hop_n = 1 * 16000   # 每满 1 秒再跑最近 2 秒
last = 0

for frame in frames:                 # frame: 1-D float32，16 kHz 单声道
    buf.append(np.asarray(frame, dtype=np.float32).reshape(-1))
    y = np.concatenate(buf)
    if len(y) < win_n or len(y) - last < hop_n:
        continue
    last = len(y)
    t0 = (len(y) - win_n) / 16000    # 本窗在开录后的起点（秒）
    result = transcribe_chunk(
        y[-win_n:],   # y: 最近 2 秒 PCM，1-D float32，16 kHz 单声道，不补零
        sess,         # ONNX 会话，load_session 返回的第一个值
        meta,         # export/meta.json，含 thresh_default / midi_lo / peak_floor 等
        t0=t0,        # 本窗起点相对开录的秒数；notes[].time = t0 + 窗内起音
        # thresh=0.8  # 可选；省略则用 meta["thresh_default"]
    )
    notes = result["notes"]
    # 只提交本窗里「新的 1 秒」，避免与上一窗重叠段重复报音
    if t0 > 0:
        notes = [n for n in notes if n["time"] >= t0 + 1.0]
```

输出


| 字段                           | 按帧 2 秒窗                          |
| ---------------------------- | -------------------------------- |
| `notes`                      | 本窗内的音符列表                         |
| `time`                       | 传入 `t0` 后为相对开录时刻；`t0=0` 则为相对本窗起点 |
| `midi` / `note` / `velocity` | 与整文件接口相同                         |


滑动方式：先攒满 2 秒才第一次推理；之后**每新进入 1 秒**，再拿**最近 2 秒**调一次（1 秒 hop、2 秒窗，相邻两次重叠 1 秒）。不是每攒满一段全新的 2 秒才调一次。


| 开录后时刻 | 送进模型的波形 |
| ----- | ------- |
| 2 s   | [0, 2]  |
| 3 s   | [1, 3]  |
| 4 s   | [2, 4]  |


注意：重叠的 1 秒会冲突：同一起音可能在相邻两窗各报一次，时间/力度也可能略有差别（两窗的 CQT 标准化不同）。`transcribe_chunk` 不会去重。

处理：第一次（窗 [0, 2]）用该窗全部 `notes`；之后只保留**新进入的那 1 秒**（`time >= t0 + 1`），重叠段以上一窗已提交的为准。不要把每次返回的 `notes` 直接无过滤地拼进总表。

### 输出（命令行 / HTTP）

```json
{
  "duration": 12.48,
  "thresh": 0.8,
  "n_notes": 3,
  "notes": [
    {"time": 0.32, "midi": 60, "note": "C4", "velocity": 86}
  ]
}
```


| 字段                 | 含义             |
| ------------------ | -------------- |
| `duration`         | 音频时长（秒）        |
| `thresh`           | 本次实际使用的 τ      |
| `n_notes`          | 音符条数           |
| `notes[].time`     | 起音时间（秒，相对文件起点） |
| `notes[].midi`     | MIDI 音高        |
| `notes[].note`     | 科学音名，如 `C4`    |
| `notes[].velocity` | 力度 1–127       |


完整示例见 `[examples/transcribe_response.example.json](examples/transcribe_response.example.json)`。

## 测试用 HTTP 接口

本机起一个 FastAPI 服务，便于用 curl / 浏览器试同一套调用。返回字段与上一节「输出」相同。

```bash
python step4_api/scripts/serve.py
```

默认 `http://127.0.0.1:8000`。交互文档：[http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)。

```bash
python step4_api/scripts/serve.py --host 0.0.0.0 --port 8000 --assets export
```

未导出模型时服务仍可启动：`GET /health` 的 `ok` 为 false，`POST /transcribe` 返回 503。

`POST /transcribe`：

```bash
curl -X POST "http://127.0.0.1:8000/transcribe" -F "file=@song.wav"
curl -X POST "http://127.0.0.1:8000/transcribe?thresh=0.8" -F "file=@song.mp3"
curl -X POST "http://127.0.0.1:8000/transcribe?path=D:/audio/song.flac"
```

JSON 体（服务与音频在同一台机器）：

```bash
curl -X POST "http://127.0.0.1:8000/transcribe" ^
  -H "Content-Type: application/json" ^
  -d "{\"path\": \"D:/audio/song.wav\", \"thresh\": 0.8}"
```

`GET /health`：

```bash
curl http://127.0.0.1:8000/health
```

```json
{
  "ok": true,
  "loaded": true,
  "onnx": "export/model.onnx",
  "thresh_default": 0.8,
  "midi_lo": 36,
  "num_pitches": 65
}
```
